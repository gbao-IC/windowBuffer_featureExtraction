# ECG RTL Integration - Codex Instructions

## Scope and repository policy
- This repository is the FPGA RTL integration fork. Work only on branch `ECG` or short-lived branches based on it. NEVER modify `main`, force push, or alter source upstream.
- The sibling repository `../AI_FSM_ECG` is the authoritative ECG training/model reference and remains read-only in this workflow. The reference commit at kickoff is `7b9a4cc4f3d7ddb1c6e47b51ab8d8a979b69fe1d`. Confirm local revision before referencing it.
- The RTL fork baseline is `9e33a48dab0d5d517ac8adaf4000dca9f8342cda`. Do not claim old RTL/tests are correct without verification.
- Follow `docs/ECG_INTEGRATION_PLAN.md`. Refactor in small, reviewable increments, each with tests and a summary of observed tool results. Do not silently replace unknown specifications.

## Product contract
- Input is SINGLE-LEAD ECG (not PPG or simultaneous multichannel ECG), from prerecorded samples for the first FPGA demo. A later optional AD8232/XADC path uses a digital sample adapter.
- Output is exactly one class ID 0..3 per accepted inference transaction: 0=Normal, 1=Fast, 2=Slow, 3=Abnormal, as generated by the CURRENT reference labeling script. These are code-specific labels, not validated medical diagnoses. Audit annotation semantics before training/model claims.
- Model is 12 feature inputs, 8 hidden ReLU units, and 4 output logits. Model training is offline on Python; only inference belongs in RTL.
- Keep ECG training features and FPGA features identical in meaning, order, units, window/event alignment, normalization, fixed-point scaling, and weight serialization.
- CURRENT training code uses beat-annotation-centered windows of 500 samples at 360 Hz, resampled to 347 samples at nominal 250 Hz; it is NOT a 500-sample/250-Hz 2-second sliding-window pipeline. Do not silently change to 512, 500@250, or 50% overlap without a versioned retraining/acceptance decision.
- Exact data format per stage MUST be documented. Raw signed-16 sample storage does not mean 16-bit ADC resolution or imply Q4.12. Q4.12 is not adequate for every raw feature/scaler value.
- `weight.hex` from current export contains 164 16-bit words (means 12; reciprocal-scales 12; FC1 weights 96; FC1 biases 8; FC2 weights 32; FC2 biases 4). Validate ordering, signedness, ROM latency, and absence of unapproved clipping before calling it a valid model package.
- Reuse generic APB/UART/FSM building blocks only when behavior is proven; eliminate PPG-only assumptions in active ECG RTL/tests/docs; don't rename a signal as a substitute for fixing behavior.

## Minimum tests and evidence
1. Run a reproducible lint/elaboration smoke test for each changed module and the top; no undriven critical clocks/resets, multi-writer registers, mismatched ports, or silent truncation.
2. Compare ECG window samples, all 12 raw features, scaler outputs, hidden values, logits and 0..3 labels against independent Python floating and bit-accurate fixed-point reference models; publish tolerances or bit-exact criteria.
3. Test negative values, overflows, min/max, zero crossings, RR units, ROM address/latency, first/last samples, back-to-back events, busy/reset behavior and UART completion.
4. Stage A: feature-vector replay -> MLP -> class output. Stage B: raw ECG replay -> window -> feature -> MLP -> class output. If external beat markers/annotation RR are injected, label the demo as oracle-assisted and do not claim independent streaming peak detection.
5. Build Vivado for ZC702 part `xc7z020clg484-1` (verify installed part listing). Timing/report claims require actual run logs, source commit and tool version. Do not claim hardware PASS from code inspection.
6. UVM/scoreboard is simulation-only; do not include UVM testbench in synthesized FPGA sources.

## Editing/reporting rules
- Before each phase: state target files, invariant behavior, new tests, and relevant unknowns. Work on one phase, then run tests and report exact commands and PASS/FAIL (or NOT RUN if tool unavailable).
- Never fabricate simulation, UVM coverage, ML accuracy or FPGA results.
- Keep training artifacts, regenerated firmware outputs and tool-generated simulations out of source except versioned, reviewed small golden vectors/model artifacts with hashes.
- No silent weakening/removal of failing tests, assertions or error checks. Keep source file provenance and license notices. 
- Do not merge or push automatically unless explicitly instructed for that phase. Working-tree edits for the requested phase are allowed.
